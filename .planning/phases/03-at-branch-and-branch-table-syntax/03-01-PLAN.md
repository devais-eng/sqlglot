**Parser (`sqlglot/parsers/parlante.py`):**

Add a `_parse_version` method override to `ParlanteParse` that handles two syntax forms:

1. `AT BRANCH <name>`: Use `self._match_text_seq("AT", "BRANCH")` to detect the two-token sequence, then `self._parse_id_var()` for the branch name. Return `self.expression(exp.Version(this="BRANCH", kind="AT", expression=<id_var>))`.

2. `@<name>` shorthand: Use `self._match(TokenType.PARAMETER)` to consume the `@` token, then `self._parse_id_var()` for the branch name. Return the same `exp.Version(this="BRANCH", kind="AT", expression=<id_var>)` AST node.

3. Fallback: Call `super()._parse_version()` for any other version syntax (Presto FOR VERSION, etc.).

The `AT BRANCH` check MUST come first (before `PARAMETER` check) because `_match_text_seq` is non-destructive if it doesn't match, while `_match` consumes the token.

Import `t.Optional` is not needed — use `exp.Version | None` return type annotation (already used in base class).

**Generator (`sqlglot/generators/parlante.py`):**

Add a `version_sql` method to `ParlanteGenerator`:

```python
def version_sql(self, expression: exp.Version) -> str:
    if expression.name != "BRANCH":
        self.unsupported(f"Parlante only supports AT BRANCH versioning, got: {expression.name!r}")
        return ""
    return f"AT BRANCH {self.sql(expression, 'expression')}"
```

This uses `self.sql(expression, 'expression')` to correctly handle both quoted and unquoted branch identifiers. Non-branch Version expressions (e.g., FOR TIMESTAMP from Spark transpilation) emit an unsupported warning and return empty string.

Note: `version_sql` is auto-discovered by the generator (the method name matches the expression class name pattern). No TRANSFORMS entry needed.

Do NOT use f-strings for the branch name — use `self.sql(expression, 'expression')` to preserve identifier quoting. The `f"AT BRANCH {self.sql(...)}"` pattern is acceptable here because the `AT BRANCH` prefix is static SQL keywords, not user data.
